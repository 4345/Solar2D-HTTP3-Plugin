# Kроссплатформенное тестовое приложение `test_app`

Универсальное приложение для визуального и автоматизированного тестирования плагина `plugin.http3` на всех платформах: **iOS**, **macOS**, **Android**, **Windows (Desktop & Simulator)**.

---

## 📁 Структура `test_app`

```
test_app/
├── main.lua          # Интерактивное дашборд-приложение с отображением памяти и контроллерами запросов
├── config.lua        # Универсальная конфигурация параметров экрана Solar2D (360x640 letterbox)
├── build.settings    # Настройки сборки и разрешения для Android, iOS, Windows, macOS
├── test_runner.lua   # CLI скрипт для запуска консольного стресс-теста на 2500 запросов
└── README.md         # Руководство по запуску
```

---

## 🚀 Как запустить приложение

### 1. Запуск в Solar2D Simulator (Windows / macOS)
1. Откройте **Solar2D Simulator**.
2. Выберите **Open Project** и укажите папку `test_app`.
3. В интерактивном окне доступны функции:
   - **1 Запрос GET**: Одиночная проверка выполнения HTTP/3 запроса на `https://cloudflare-quic.com`.
   - **Пачка 50 REQ**: Запуск 50 параллельных запросов для проверки пропускной способности.
   - **Очистить GC**: Принудительный запуск сборщика мусора и обновление физических метрик памяти (`Native RSS`).
   - **Тест Cancel**: Выполнение отмены выполняющегося запроса по ID (`http3.cancel(reqId)`).
   - **Инфо о нативном стеке**: Вывод данных о задействованном стеке (`MsQuic + WinHTTP`, `Cronet`, `Network.framework`).

### 2. Сборка под Android
1. В Solar2D Simulator выберите **File -> Build -> Android**.
2. Приложение автоматически подтянет плагин `plugin.http3` и сгенерирует `.apk` / `.aab`.

### 3. Сборка под iOS / macOS
1. В Solar2D Simulator выберите **File -> Build -> iOS** (или **macOS**).
2. Приложение соберется с использованием нативного стека Apple `NSURLSession` с параметром `assumesHTTP3Capable = YES`.

## `proba_progressa.lua` — прогресс передачи

Стенд опросного слоя (Windows): проверяет, что счётчики нативной части доходят
до вызывающего фазами `began` / `progress` / `ended`.

```
"C:\Program Files (x86)\Corona Labs\Corona\Native\Corona\win\bin\lua.exe" proba_progressa.lua
```

Пять случаев и что в них ожидается:

| случай | ожидание |
| :--- | :--- |
| 1. приём, длина известна | `bytesEstimated` равен `Content-Length`, итог совпадает с длиной тела |
| 2. приём по HTTP/3 | фазы идут, `bytesEstimated` равен `-1` — у QUIC длина тела до разбора кадров неизвестна |
| 3. отправка | **только** `began` и `ended`: тело уходит одним куском, промежуточным значениям взяться неоткуда |
| 4. без `progress` | ноль промежуточных событий |
| 5. пачка из 50 | все завершились, слотов хватило, активных задач по завершении ноль |

Первая строка вывода — `progress_podderzhivaetsya()`. `false` означает, что
библиотека собрана без `checkProgress`, и остальные случаи смотреть незачем.

В CLI нет кадрового цикла Solar2D, а опрос обёртки живёт на `enterFrame`,
поэтому стенд подставляет `Runtime` и крутит кадры сам. Без этого не пришло бы
вообще ничего, и это была бы не вина плагина.
